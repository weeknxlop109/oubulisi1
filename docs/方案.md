# 医药知识图谱问答系统 · 方案 A（PPT 原路线）

> 离线知识生产 + 在线问答：实体识别 → 意图分类 → 参数化 Cypher → 模板答案，全程可追溯、不编造。

## 1. 做法

### 1.1 总体架构

```
[离线知识生产]                     [在线问答]
URL/文档 ─▶ 采集(crawler) ─▶ 解析(parser) ─▶ 清洗(clean)
                                            │
                    词典(segment) ◀── 实体抽取 ─┤
                                            ▼
        本地图存储(graph.json, MERGE 去重) ◀── 建图(build_graph)
                │                                 │
                ▼                                 ▼
        题库自动生成(question_bank) ◀──────────  实体词典
                │
                ▼
   BiLSTM-CRF NER + TextCNN 意图 (train.py, 8:1:1, best-f1 保存)
                                            │
[演示] FastAPI(GUI.py) ◀────────────────────┘
   / 网页 PWA · /ask · /health · /admin/* · mobile/ APP 壳
```

### 1.2 图谱 Schema

- **5 类 Label**：`Disease / Drug / Symptom / Check / Prevent`
- **5 类关系**：`HAS_DRUG / HAS_SYMPTOM / NEED_CHECK / PREVENTS / ALIAS_OF`，方向统一 `Disease → 目标实体`
- 节点唯一约束：按 `Label + name` MERGE 去重（重跑建图节点数不翻倍，verify V2 判据）

### 1.3 9 类问句

4 类第一版实现并纳入回归：**用药 / 症状 / 检查 / 预防**；
另 5 类（治疗方案 / 治疗周期 / 并发症 / 药物相互作用 / 症状推疾病）显式标注「待扩展」并给出扩展路径，命中时返回 `status=pending`，不静默缺失（VA7 / A-V2 判据）。

### 1.4 问答链路与 4 级兜底

`question → tokens → entity → intent → cypher → answer` 六步，每步中间产物写入 `trace` 并分渠道落日志（preprocess / ner / cls / query）。

| 状态 | 触发 | 行为 |
|---|---|---|
| `ok` | 实体+意图高置信且查图命中 | 模板答案 + Cypher 证据路径 + 安全提示 |
| `empty` | 查图无行 | 拒答，不编造 |
| `clarify` | 置信度 < 0.75 或实体不明 | 请求补充信息 |
| `safety` | 高风险关键词（孕/婴/急/血…） | 优先于空结果，建议就医 |
| `pending` | 命中待扩展意图 | 标注待扩展 + 扩展路径 |

### 1.5 上下文记忆

`session_id` + 最近 5 轮会话；指代追问（"那要注意什么"）沿用上轮实体改写后重查（A-V7 判据）。

## 2. 依赖

仅使用本机/镜像已装包：`torch / numpy / scikit-learn / fastapi / uvicorn / python-dotenv / matplotlib / pypdf`（见 requirements.txt，不新增依赖）。
MongoDB / Neo4j 驱动不在环境内，故用**本地 JSON 图存储 + 参数化 Cypher 子集执行器**（`cypher_engine.py`），模板与真实 Neo4j Cypher 同构，可无缝替换驱动。

## 3. 实施步骤

| 步骤 | 内容 | 入口 |
|---|---|---|
| 1 | 配置中心（`.env` + config.py） | `config.py` |
| 2 | Schema 定义（Label/关系/意图/高风险词） | `schema.py` |
| 3 | 采集 / 解析 / 清洗 | `crawler.py` / `parser.py` / `clean.py` |
| 4 | 双向最大匹配分词 + 实体词典 | `segment.py` |
| 5 | 本地图存储 + MERGE 建图 + 参数化 Cypher | `graph_store.py` / `build_graph.py` / `cypher_engine.py` |
| 6 | inbox 自动入库（哈希去重、幂等、审核开关） | `kb/auto_add.py` |
| 7 | 题库自动生成 + 回归验证 | `kb/question_bank.py` |
| 8 | BiLSTM-CRF NER + TextCNN 意图训练（best-f1 保存 + 曲线） | `train.py` / `ner_cls.py` |
| 9 | 问答链路 + 4 级兜底 + 上下文 + FastAPI + PWA + APP 壳 | `qa_service.py` / `GUI.py` / `web/` / `mobile/` |
| 10 | 备份（打包+敏感扫描+git）+ 图谱体检修复 + 全量验证 | `backup/` / `graph_doctor.py` / `verify.py` |

初始化一键执行：`./up.sh` / `.\up.ps1`（含 init：入库→建图→题库→训练）；全量验证：`./verify.sh` / `.\verify.ps1`（18 项判据）。

## 4. 演示设计

1. **正常问句**：「风热感冒吃什么药」→ ok 徽标 + 药物 chips + Cypher 证据路径 + 安全提示 + 耗时（总/模型/查询）。
2. **空结果**：「量子纠缠怎么影响股票」→ empty，拒答不编造。
3. **高风险**：「孕妇胸闷气短怎么办」→ safety，建议就医。
4. **待扩展**：「感冒怎么治疗」→ pending + 扩展路径说明。
5. **上下文**：先问「感冒吃什么药」再问「那要注意什么」→ 沿用上轮实体答预防。
6. **自动入库**：向 `data/inbox/` 投放新 md → 同步 → 节点/题库增加且新内容可被问句命中。
7. **备份**：`POST /admin/backup/run` → 打包 + 敏感扫描报告（dry_run 止步）。
8. **多端一致**：网页 / PWA 主屏 / 移动端 APP 壳（mobile/index.html）同一问句返回一致答案。
